# 공통 외부 시간 예산과 기존 알고리즘 비교

**한국어** | [English](deep-protocol.md) | [소스 빌드](deep-runtime.ko.md)

V3 프로토콜은 두 참가자에게 공통 외부 시계와 같은 시간 배분 규칙을 적용합니다. 기존 제출본과 개선 엔진의 서로 다른 내부 시간 관리 방식이 알고리즘 비교에 미치는 영향을 구분하기 위한 구조입니다.

## 요청 형식과 참가자 식별

기존 V2 요청을 계속 지원합니다.

~~~text
V2;R|B;size;START|CHANGE|SWAP;previous_move;board;turn
~~~

V3는 현재 수에 배정한 탐색 시간과 외부에서 측정한 남은 경기 시간을 추가합니다.

~~~text
V3;R|B;size;START|CHANGE|SWAP;previous_move;board;turn;allocated_search_seconds;external_remaining_seconds
~~~

심판은 스왑 이후를 포함해 요청마다 현재 색상을 전달합니다. 색상이 바뀌어도 시간 계정은 참가자 식별자에 연결되므로 다른 참가자의 시간과 섞이지 않습니다. 네이티브 프로세스는 stdout에 좌표 하나를, stderr에 JSON 진단 정보를 출력합니다.

배정 시간과 남은 시간은 유한한 0 이상의 값이어야 합니다. 엔진은 두 값 중 작은 값과 경기 상한, 명시된 수별 상한을 적용합니다. 별도의 탐색 횟수 제한이 없으면 V3는 배정한 종료 시각까지 탐색합니다. 남은 시간이 0이면 합법적인 대체 수를 선택하고 그 이유를 기록합니다. 이미 끝난 보드나 잘못된 입력은 거부합니다. 최종 시간 제한과 실행 실패 판정은 독립적인 심판이 수행합니다.

## 배분 규칙과 전체 시간 기록

공통 배분기는 남은 시간에서 입출력 여유 시간을 뺀 뒤, 예상 남은 판단 횟수와 최소 미래 판단 횟수 중 큰 값으로 나눕니다. 처음에는 참가자가 총 24번 판단할 것으로 가정합니다. 고정한 300초 설정은 expected_actor_moves=24, minimum_future_actor_moves=8과 io_reserve_seconds=0.05를 사용하므로 처음 배정하는 탐색 시간은 약 12.498초입니다. 이후에는 실제 소비 시간을 반영하고, 최소 8번의 미래 판단에 쓸 시간을 고려해 경기 후반의 여유를 남깁니다.

외부 측정에는 C++ 내부 시계가 직접 측정하지 못하는 프로세스 입출력 시간이 포함됩니다. 각 요청의 배정 시간, 남은 예산, 프로토콜 메시지, 응답 시간과 실패한 요청도 보존합니다. 기록 재생으로 참가자별 시간 계정과 V3 메시지를 다시 계산합니다. 요청에 실패해도 소요 시간은 기록하며, 존재하지 않는 수나 승자를 만들어 넣지 않습니다.

예산 모드별로 확인하는 내용은 다음과 같습니다.

| 모드 | 주된 통제 조건 | 해석 |
| --- | --- | --- |
| iterations | 한 수에서 모든 워커가 수행한 총 시뮬레이션 횟수 | 같은 탐색량에서의 비교 |
| time | 수별 시간 상한과 전체 경기 상한 | 정해진 수별 시간에서의 판단 |
| game_time | 공통 적응형 배분 규칙과 외부 참가자별 경기 상한 | 같은 경기 시간 예산에서의 판단 |

300초 상한은 모든 경기에서 해당 시간을 전부 사용한다는 의미가 아닙니다. 시작 수나 스왑, 즉시 승리와 방어는 시뮬레이션 없이 수를 결정할 수 있고, 경기가 일찍 끝나면 남은 시간을 사용하지 않습니다.

## 서로 다른 세 가지 과거 비교

| 참가자 | 보존한 내용 | 해석의 범위 |
| --- | --- | --- |
| 개선 엔진의 legacy_ts | 공통 엔진 안에서 비활성 AMAF와 기존 직접 통계 감쇠를 적용한 진단 조건 | 원본 제출본 자체와의 비교를 대신하지 않음 |
| 원본 소스의 legacy | 보존한 기존 C++ 소스를 별도로 빌드한 구현 | 내부 시간 배분을 바꾸지 않으면 공통 외부 시간 비교와 다름 |
| benchmark_legacy | 원본 알고리즘에 기록 가능한 실행 계층만 적용한 비교용 어댑터 | 원본 배포 실행 파일과 바이트 단위로 동일한 실행은 아님 |

비교용 어댑터는 V3 요청 처리, 시드가 고정된 워커 난수열, 워커 수 설정, 외부 종료 시각 확인과 진단 출력을 추가합니다. 생성 전에 원본 소스 해시를 확인하고, 정확히 일치하는 코드만 교체해 변경 기록을 남깁니다. 보드와 확장 로직, 선택과 롤아웃, 보상, 스왑과 전술 알고리즘은 유지합니다. 기존의 비활성 RAVE 동작과 워커당 1,500,001회 상한도 그대로 기록합니다. 생성된 C++와 변경 기록은 결과와 함께 공개합니다.

Windows 실행 파일명 수정은 컴파일 결과를 설치하는 방식에 한정됩니다. 생성된 알고리즘 영역과 해당 해시는 바뀌지 않습니다.

## 선후공 비교와 실패 분모

선후공 한 쌍은 같은 시작 조건과 시드, 장비 할당, 실행 파일 소스와 워커 수를 사용합니다. 모든 경기에 장비 및 어댑터 식별 정보를 연결하고, 한 쌍에서 이 정보가 다르면 거부합니다. 통합 집계는 같은 장비와 어댑터 조건에 속한 완전한 선후공 쌍을 재표집하며, 환경별 결과도 제공합니다.

장비 해시는 CPU와 자원 할당의 유형을 구분하며, 물리적 장비 하나를 고유하게 식별하지는 않습니다. 실행 호스트 이름의 해시도 물리적 장비의 동일성을 입증하는 정보는 아닙니다. 같은 실행에서 선후공을 비교했다는 근거는 한 쌍을 한 실행에 배정하고 해당 실행의 출처를 보존하는 방식으로 확보합니다. 두 경기가 서로 다른 실행 폴더에 있으면 장비 해시가 같아도 공개 검증기가 거부합니다. 세션을 다시 시작한 경우에는 별도의 실행 기록을 남기고, 다른 세션의 부분 경기 두 개를 하나의 쌍으로 합치지 않습니다.

완료 경기 승률과 함께 예정 경기당 검증된 승리, 실패와 누락, 완전한 선후공 쌍을 표시합니다. 시간 초과, 프로토콜 오류, 불법 수와 프로세스 실패는 실행 실패로 남기며 경기력에 따른 승리로 바꾸지 않습니다. 선후공 두 경기는 독립적이지 않으므로 경기 단위 Wilson 구간은 참고 수치로 제공합니다.

확장 실험에서는 기존에 선택한 설정을 유지합니다. 고정된 전술 제거 실험은 스왑 판단, 즉시 승리와 상대 즉시 승리 방어의 영향을 각각 설명하는 용도이며, 새로운 설정 선택이나 채택 실험은 아닙니다. 이전 브리지와 수 정렬, RAVE 가중치 후보 중 채택 기준을 만족하지 못한 조건은 중단한 상태로 유지합니다. 구현 정확성 수정은 별도의 테스트로 검증합니다.

## 최신 공개 도구의 실제 실행 근거

시간 제한을 적용한 최신 공개 도구 v3의 통합 실행에서 Python 테스트 107개와 C++ 자체 검증, sanitizer 프로토콜 테스트 6개가 통과했습니다. 참가자별 시간 5초를 적용한 V3 대국 4개도 실패 없이 끝났으며, 기록한 메시지와 색상 변경, 외부 시간 계정을 포함해 100수를 재생 검증했습니다. 짧은 통합 실행 경로를 확인한 결과이며, 전체 300초 예산의 경기력 실험을 대신하지 않습니다.

별도의 실제 v3 체크포인트 작업은 공통 시간 예산의 전체 400경기 중 첫 번째 묶음에 40경기와 선후공 20쌍을 배정했습니다. 이 작업도 소스 빌드와 Python 테스트 107개, C++ 자체 검증과 sanitizer 검사를 마쳤지만, 평가기의 시간 제한으로 첫 평가 대국 전에 멈췄습니다. 결과에는 checkpointed와 기록된 경기 0개, 배정 범위의 미실행 경기 40개, 전체 미완료 상태가 정확히 남았습니다. 이 결과는 실행 배정과 결과 저장의 근거이며 V3 대국 판단이나 경기력의 근거는 아닙니다. 최초 공개 도구 v1과 v2b의 결과는 당시 소스 버전에 연결한 별도 기록으로 보존합니다.
