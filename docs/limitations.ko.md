# 검증 범위와 보존한 실험

**한국어** | [English](limitations.md) | [프로젝트 개요](../README.ko.md)

구현 정확성, 경기력, 처리량과 환경 이식성은 각각 다른 근거로 판단합니다. 한 항목의 테스트 통과나 높은 점수가 다른 항목까지 입증하는 것은 아닙니다.

이전 6개 평가 설정과 집계, 소스 버전 정보와 저장된 532경기는 그대로 보존합니다. 당시 엔진과 실행부 소스 13개를 담은 압축 파일로 16,768수를 재생 검증합니다. V3 확장 결과는 추가 근거로 제공하며 이전 실험을 대체하지 않습니다. 원본 프레임워크와 배포 자료, 과거 경기 기록 64개도 별도 해시 목록으로 보존합니다.

시간 제한을 포함한 최신 공개 도구 v3의 Kaggle 통합 실행에서 Python 테스트 107개를 건너뛰지 않고 통과했으며 C++ 자체 검증과 sanitizer 프로토콜 테스트 6개도 통과했습니다. 짧은 V3 대국 4개가 모두 실패 없이 완료됐고 저장한 100수를 재생 검증했습니다. 패키징, 재빌드, 프로토콜 호환성, 소스 해시와 경기 기록 저장까지 확인한 결과입니다. 짧은 대국 4개만으로 경쟁력 있는 승률을 주장하지 않습니다. C++ 자체 검증과 ASan 및 UBSan은 명시한 사례를 확인하며, 가능한 모든 입력이나 컴파일러, 실행 부하에 오류가 없다는 보장은 아닙니다.

별도로 실제 실행한 v3 체크포인트 작업도 자체 Python 테스트 107개와 C++ 및 sanitizer 검증을 통과한 뒤 첫 평가 대국 전에 멈췄습니다. 전체 400경기의 10개 묶음 중 첫 번째에 40경기와 20쌍을 배정했으며, 결과 ZIP에는 기록된 경기 0개, 배정 범위의 미실행 경기 40개, checkpointed와 전체 미완료 상태가 정확히 남았습니다. 의도적으로 지정한 실행 시간 1초는 빌드와 테스트 이후 평가기의 중단을 확인하는 설정이며 전체 실행이 1초 안에 끝난다는 의미는 아닙니다. 이 결과를 경기력 근거의 경기 수나 승리 수에 더하지 않습니다. 최초 공개 도구 v1과 v2b 결과는 각 소스 압축 파일에 연결한 별도 기록으로 유지하며 최신 v3 검증으로 바꾸거나 최신 통합 경기 집계에 중복으로 넣지 않습니다.

공통 외부 시계는 실행 시간 예산을 맞추지만, 초기 알고리즘과 개선 엔진의 모든 차이를 개별적으로 분리하지는 못합니다. 비교용 어댑터는 워커 난수열과 실행 시간 관리, 프로토콜과 진단 출력을 바꿉니다. 검사한 알고리즘 영역은 보존하고 초기의 워커당 1,500,001회 상한도 유지해 공개합니다. 이 상대에 대한 성능 차이는 어댑터와 명시한 시작 조건, 시드와 보드 크기, 장비 범위에서 해석합니다.

고정 탐색 횟수와 공통 시간 예산의 점수는 서로 다른 질문에 답합니다. 전술로 판단하면 시뮬레이션 없이 수를 결정할 수 있고, 300초 예산을 일부만 사용할 수도 있습니다. 실제 참가자별 소비 시간과 실패를 결과와 함께 제공합니다. 고정한 보드 상태의 처리량이 전체 경기의 일반적인 속도를 나타내지는 않으며, 워커 수가 물리적 CPU 성능과 같은 의미도 아닙니다.

이전 개발 후보는 점추정 하나가 높다는 이유만으로 채택하지 않았습니다. 사전에 정한 선후공 쌍 기준과 불확실성으로 판단했으며, 중단한 후보의 결과도 보존합니다. 고정된 확장 전술 제거 실험은 설정 선택을 다시 진행하지 않고 기능의 영향을 설명합니다. 실패율과 예정 경기당 검증된 승리를 함께 제시해 완료 경기 승률이 실행 문제를 가리지 않도록 합니다.

기록 재생은 규칙과 색상 변경, 시간 기록과 승리 연결을 확인합니다. 탐색을 다시 실행하거나 수가 전략적으로 최적이었다는 사실을 확인하는 절차는 아닙니다. 컴파일러와 표준 라이브러리 버전에 따라 실행 파일 바이트와 확률적 탐색 경로가 달라질 수 있습니다. 같은 장비에서도 시간 기반 대국 결과는 반복 실행마다 달라질 수 있습니다.

로컬 Windows와 Kaggle Linux는 같은 프로젝트 운영자가 사용한 서로 다른 환경이며, 독립적인 외부 검토자의 검증은 아닙니다. Davis는 과거 프로젝트의 온라인 사이트 상대이고 HexHex도 과거에 대국한 상대입니다. 해당 실행 파일과 정확한 실행 설정을 포함하지 않으므로, 새로운 내부 평가로 과거 대국을 독립적으로 재현하거나 일반적인 Hex 순위를 주장하지 않습니다.

새 소스 ZIP은 개선 소스와 초기 프로젝트 자료를 함께 제공합니다. 인증정보나 개인 실행 기록, 새로 빌드한 장비별 실행 파일은 공개 소스에 포함하지 않습니다. 현재 운영체제에 맞게 개선 엔진을 빌드합니다. 초기에 배포한 Linux 실행 파일은 과거 자료이며 Windows와 모든 Linux 환경에서 사용하는 공통 실행 파일이 아닙니다.

## 실제 추가 실험의 해석

공통 시간 평가 400경기와 전술 제외 평가 400경기는 모두 실패나 미기록 없이 완료했습니다. 공통 시간 평가의 선정 정책 승리는 초기 알고리즘 어댑터 81/100, RAVE-UCB 84/100, TS 73/100, UCB 70/100입니다. 이 수치가 모든 장비에서의 우위를 뜻하지는 않습니다. UCB 상대 Windows 구간은 9/20이었으며, 장비별 분포와 선후공 쌍 50개를 기준으로 한 신뢰 구간을 [실험 문서](experiments.ko.md)에 함께 제공합니다.

공통 시간 평가의 네이티브 요청 18,514개와 참가자 및 경기 조합 800개에서 외부 시간 한도 위반은 0건이었습니다. 개선 엔진의 워커 노드 한도 도달은 30,078개 관측 중 27,298개였습니다. 도달 이후에도 롤아웃을 계속하므로 탐색 실패를 나타내지 않습니다. 초기 알고리즘의 메모리 할당 구조는 보존했으므로 동일한 시간과 워커 수를 맞춘 결과를 동일한 RAM 상한 실험으로 설명하지 않습니다. RSS는 실제 측정한 프로세스 메모리이며 운영체제가 강제하는 메모리 한도와 다릅니다.

전술 제외 실험은 스왑 검사 제외 상대에 51/100, 즉시 승리 검사, 즉시 방어 검사 및 두 검사 모두 제외한 상대에 각각 50/100을 기록했습니다. 관측된 쌍 점수가 모두 0.5이면 재추출 구간이 50–50%로 축소되지만, 이를 정확한 모집단 승률이나 기능 동등성의 증거로 해석하지 않습니다. 동일한 입력에서의 일부 전술 응답 시간 감소는 조건부 측정이며 전체 에이전트 속도 향상을 의미하지 않습니다.

각 운영체제에서 여섯 상태와 네 워커 설정을 각각 7회 측정한 168개 요청은 고정된 순서로 실행했습니다. 7회 표본의 p95는 정밀한 운영 지연 추정치가 아닙니다. Windows와 Kaggle의 성능 비교는 운영체제뿐 아니라 CPU와 컴파일러도 함께 달라지므로 특정 원인의 효과로 분리할 수 없습니다. Kaggle의 8워커는 관측된 4개 CPU 할당을 공유했으며, 8개 코어가 제공되었다는 의미가 아닙니다.
